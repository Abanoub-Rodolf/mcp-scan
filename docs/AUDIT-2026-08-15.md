# mcp-scan Security & Correctness Audit — 2026-08-15

End-to-end audit of the mcp-scan codebase (16 scanners, 19 commands, CLI core, data
modules, test suite, CI, docs). Every claim below was verified against live source
with line numbers, runtime probes, or the test suite. All fixes are committed with
regression tests; the suite grew from 213 to 244 tests and passes clean.

## Method

- 4 parallel audit passes: scanners/data modules, commands/utils/CLI core,
  tests/CI/isolation, docs/claims/metadata.
- Runtime probes for regex behavior (ReDoS, lastIndex traps, FP/FN cases).
- `npm audit`, `tsc --noEmit`, full vitest suite, golden-file CLI runs.
- 15 fix commits, each scoped to one problem class, all green.

## Critical fixes

| # | Finding | Fix |
|---|---------|-----|
| 1 | Stored XSS in HTML reports: every server-controlled string (tool descriptions, finding text, config paths) was interpolated unescaped; a malicious config produced a report that runs JS in a browser | `escapeHtml` on all interpolated values + XSS regression test |
| 2 | Command injection in `mcp-scan doctor`: `execSync("which " + server.command)` executed attacker-controlled config values through a shell | `spawnSync('which'/'where', [cmd])` with no shell |
| 3 | Proxy wrote raw unmasked JSON-RPC payloads to `~/.mcp-scan/logs` before PII masking ran, and tests polluted the real home dir (EPERM unhandled error) | mask before logging; `MCP_SCAN_LOG_DIR` override; unwritable log degrades gracefully; stream error listener |
| 4 | Secret scanner: Pinecone/Heroku patterns flagged every UUID as CRITICAL; Cloudflare/Railway/Together flagged any 40/36/64-char string; a `hf_` test passed only because of the Railway false positive | prefix-less formats gated by env-key context; added `github_pat_`, `rk_live_`, `whsec_`; percent-decoded matching; `server.url` scanned; non-string env values no longer crash |
| 5 | PII cascade: bare 24-64 char "API key" regex, non-Luhn card regex, and IP/zip/NPI/DL patterns flagged ordinary configs CRITICAL; `/g` + `.test()` lastIndex bug silently disabled PII detection from the second server on | Luhn validation, private-IP exclusion, keyword-gated numeric shapes, word-boundary terms restricted to descriptive text, patterns stored without `/g` |
| 6 | CVE scanner: OSV findings with CVSS v4 or plain numeric scores were silently dropped; the upgrade advisor recommended upgrades exactly when they fixed nothing; committed snapshot contained a fake CVE and 143-day-old data | any-format score parsing with qualitative fallback; upgrade resolves when latest >= fixed; snapshot regenerated from live data (74 packages, real GHSA entries) |

## High-impact fixes

- JSONC parser corrupted valid configs (URLs containing `,}` lost characters; URLs +
  trailing comments failed to parse) → string-state machine with regression tests.
- `fix` command made 0600 secrets files world-readable and replaced symlinks →
  preserves mode, resolves symlinks, timestamped backups.
- Plain `mcp-scan` exited 1 on critical/high; strict exit codes are now a `--ci`
  contract as documented.
- Default scans silently skipped CVE/supply-chain/license scanners → they always run
  (README documented the network lookups; `--offline` disables).
- A throwing scanner aborted the whole run → per-scanner isolation with a LOW
  `scanner-error` finding.
- ast/network-egress/prompt-injection/tool-poisoning/permission/config scanners had
  systematic false positives: substring domain whitelists, `nc` flags as reverse
  shells, `--experimental-*` as `-e`, POST inside "postgres", read+write verb
  co-occurrence as capability escalation, exact-match permission paths, `${apiKey}`
  as CRITICAL shell injection.
- `ci --output` was declared but dead; `privacy --output` implemented but undeclared;
  `sbom --include-deps` accepted but nonexistent; `audit` deep-checked the wrong
  server; `report` swallowed per-file errors; `submit` had no fetch timeout; webhook
  leaked timers; SBOM purls were invalid for names with spaces; compliance produced
  NaN scores.
